# Мобільний застосунок CharityPlatform

**CharityPlatform** — це мобільний застосунок для керування благодійними кампаніями організації. Метою розробки було створити додаток для платформи Android, де реалізувати базові CRUD-операції для сутності Кампанія.
___
##  Стек технологій
*   **Мова та середовище розробки:** Java, Android Studio
*   **База даних:** SQLite.
*   **Доступ до даних**: Room ORM. Використано патерн **Singleton** для ініціалізації бази даних.
*   **Архітектурний підхід:**
    * Використання **DAO** (Data Access Object) для визначення SQL-запитів.
    * Реалізація проміжного шару **Repository** (`CampaignRepository`) для ізоляції доступу до даних від користувацького інтерфейсу.
*   **Багатопотоковість**: Всі операції з базою даних винесені у фонові потоки за допомогою `ExecutorService`. Повернення результатів у головний потік (UI Thread) реалізовано через патерн `Callback` та `Handler`.
*   **UI/UX**:
    * Декларативна розмітка екранів (XML). 
    * Віджет `ListView` з кастомним адаптером `CampaignAdapter` та використанням `ViewHolder` для оптимізації рендерингу списку. 
    * Повноцінна підтримка **Світлої та Темної тем** оформлення через ресурси `values` та `values-night`.
---
##   Функціональність та бізнес-логіка

1.  **Перегляд списку кампаній (Read):** Головний екран відображає перелік усіх поточних кампаній із зазначенням прогресу збору коштів, а також _загальну статистику_ (загальна сума зборів та кількість успішних кампаній).
2.  **Створення кампанії (Create):** Додавання нового збору через спеціальну форму з використанням зручних UI-компонентів (`DatePickerDialog` для вибору дат та `Spinner` для вибору організації).
3.  **Редагування та внесення пожертв (Update):** Можливість змінити опис кампанії, дати, цільову суму, а також функціонал додавання нових транзакцій (внесків) до поточної суми збору.
4.  **Видалення (Delete):** Можливість видалити кампанію з бази даних, з урахуванням суворих правил бізнес-логіки.

Застосунок містить надійну систему перевірки введених даних для забезпечення цілісності системи:
* **Захист фінансових даних:** Видалення кампаній, які вже мають ненульову поточну зібрану суму (вже отримали пожертви), суворо заборонено.
* **Валідація дат:** Дата початку кампанії не може бути в минулому часі. Дата завершення обов'язково має бути пізнішою за дату початку.
* **Валідація тексту:** Перевірка формату ПІБ організатора, назви кампанії на мінімальну довжину та відсутність порожніх полів.
* **Автоматизація:** Статус `is_target_reached` розраховується автоматично при кожній зміні цільової або поточної суми.
